# SEO-аудит сайта АПВ — СИСТЕМА (Яндекс + Google)

**Дата:** 2026-04-23 · **Роль:** 04 (SEO + оркестратор) · **Объект:** кодовая база `apv-b2b-landing` (Next.js 14, App Router, next-intl).

**Метод:** статический разбор конфигурации и шаблонов метаданных **без** доступа к прод-домену, Вебмастеру и Search Console — позиции и трафик в отчёт **не** включались.

---

## Резюме

| Уровень | Оценка |
|---------|--------|
| Техническая база (canonical, robots, мета-API Next, JSON-LD) | **Хорошо** при корректном `NEXT_PUBLIC_SITE_URL` в проде |
| Охват URL в sitemap | **Требует внимания** — программатика «профессия×город» только во втором sitemap |
| Контентная масштабируемость (сотни programmatic) | **Риск умеренный** — нужен контроль уникальности и мониторинг качества в Вебмастере |
| Готовность к Яндексу/ Google | **Готово к подключению** верификации и мониторинга; поведенческие/CWV — только полевые данные |

## 1. Индексация и обход

### 1.1 `robots.ts`

- Разрешён весь сайт кроме `/api/` и `/admin`.
- Указаны **два** источника карт: `sitemap.xml` и `/api/sitemap-programmatic` — роботы смогут подтянуть programmatic URL.

**Риск:** если поисковик по умолчанию опирается только на первый sitemap из списка — зависит от краулера; для надёжности позже рассмотреть **sitemap index** (один файл-индекс со ссылками на части).

### 1.2 Редиректы (`next.config.mjs`)

- Есть постоянные редиректы со старых slug блога и услуги `/uslugi/autstaffing` на статью — **плюс** для сохранения ссылочного веса и единого каноникала.

### 1.3 Локаль (`next-intl`)

- `localePrefix: "as-needed"`, единственная локаль `ru` — публичные URL **без** префикса `/ru`, что согласовано с `absUrl()` и canonical в `buildPageMetadata`.

## 2. Canonical, метаданные, Open Graph

### 2.1 `buildPageMetadata` (`src/lib/seo.ts`)

- Единый шаблон: `title | бренд`, `description`, `alternates.canonical`, `robots: index,follow`, Open Graph + Twitter card.
- **`keywords`** передаётся опционально — на страницах без массива keywords Google их не получит (это нормально).

### 2.2 `metadataBase` (`src/app/[locale]/layout.tsx`)

- Задаётся через `site.url` → **в продакшене обязательно** выставить `NEXT_PUBLIC_SITE_URL` на боевой HTTPS-домен с финальным видом (www / non-www), иначе OG URLs и canonical в превью будут указывать на localhost или тест.

### 2.3 Верификация поисковиков

- В layout подключены `verification.google` и `verification.yandex` из env — в `.env.example` значения **пустые**. Для выдачи нужно заполнить в проде.

### 2.4 `opengraph-image.tsx`

- Есть динамическое OG-изображение 1200×630 — **плюс** для шаринга и части соц/поисковых сценариев.

## 3. Sitemap

### 3.1 Основной `src/app/sitemap.ts`

- Покрывает: статические маршруты, хабы из `allMultipageSeoPaths()`, хабы профессий `/personal/{slug}`, **все** посты блога (через `BLOG_POSTS` из `blog-stub` → синхрон с `blog-published`), кейсы `/keysy/{slug}`.

### 3.2 Программатика «город × профессия`

- URL вида `/personal/{profession}/{city}` **не** входят в основной `sitemap.ts`.
- Полный список отдаёт **`GET /api/sitemap-programmatic`** (XML).

**Вывод:** технически обход возможен через `robots`, но для единообразия и контроля (особенно Google) целесообразно в следующей итерации: **либо** объединить в sitemap index, **либо** добавить programmatic в основной sitemap батчами с учётом лимита размера файла.

### 3.3 Актуальность `lastModified`

- Для многих статических URL выставлена **одна** дата сборки — сигнал свежести слабый. Для блога используется `publishedAt` — **хорошо**.

## 4. Структурированные данные

- **Главная:** `Organization` + `WebSite` (`page.tsx`).
- **Услуги / коммерческие посадочные:** `Service` + `FAQPage` где подключено в компонентах.
- **География / хабы:** `WebPage`.
- **Блог:** `BlogPosting` с `author`/`publisher` как **Organization** — допустимо для «Редакция»; при желании усилить E-E-A-T можно добавить реального автора/ Person (не обязательно для старта).

**Рекомендация:** прогнать страницу через [Rich Results Test](https://search.google.com/test/rich-results) и аналогичную проверку Яндекса после деплоя на прод-домен.

## 5. Контент и программатика (SEO-риски)

- Сотни страниц **профессия × город**: при слабом различии текстов возможны **дубли по смыслу** (Яндекс чувствительнее к шаблону).
- В коде уже есть локальные и профильные вставки (`programmatic-longread.ts`, локальные нарративы) — **правильное направление**.
- **Роль 03** должна ограничивать «размытие» коммерческого сообщения ради ключей.

## 6. Яндекс vs Google — приоритеты доработок

### Яндекс

1. Регистрация в **Яндекс.Вебмастере**, регион сайта (Москва/МО по смыслу услуги).
2. Контроль **дублей** и качества программатики в отчётах.
3. Согласованность **НЕЙРО NDA** не применимо — но адрес, телефон, оферта должны быть консистентны с реальным ИП.

### Google

1. Подключить **Search Console**, проверить покрытие индекса и причины исключений.
2. **PageSpeed Insights / CrUX** после продакшена — не измерено в этом аудите.
3. Проверка мобильной версии и CLS при motion/шрифтах — см. UX-роль.

## 7. Критичные действия перед «боевым» SEO

| # | Действие |
|---|----------|
| P0 | Выставить **`NEXT_PUBLIC_SITE_URL`** на финальный HTTPS-домен |
| P0 | Заполнить **`NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`** и **`NEXT_PUBLIC_YANDEX_VERIFICATION`** |
| P1 | Решить судьбу **двух sitemap** (index или объединение programmatic) |
| P1 | Пройти Вебмастер + GSC после первого прод-деплоя и исправить ошибки обхода |
| P2 | Точечный аудит title/description на топ-50 URL по объёму запросов (после накопления статистики) |
